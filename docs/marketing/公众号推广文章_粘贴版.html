📢 v2.0.5 上线

这个工具最早只做一件事：检测到 5 小时限制 → 等到 reset 时刻 → 自动输入 continue。v2.0 起它多了两个身份：被安全策略拦住时自动换模型顶上（模型恢复），以及 v2.0.5 新增的 After finish —— 会话跑完当前任务后，自动输入你预设的下一条指令，让窗口一直有活干。已经在用旧版本的朋友，直接看 "⏭ After finish" 和 "⇄ 模型恢复" 两节。

跑 Claude Code 长任务的朋友，下面这些场景应该都经历过：

⚠ 日常之痛
  • 睡前丢一个长任务给 Claude，醒来发现两小时后就被 limit 弹回去了，剩下的活全没干。
  • 写安全相关的代码，被模型的安全策略判定为敏感内容，整轮直接停住，人不在就一直停着。
  • 网络抖一下就卡死，得手动敲 continue 才能恢复。
  • 同时开 3、4 个 Windows Terminal 跑不同分支，谁被卡了、谁又恢复了，得挨个去翻。

这是一个完全开源的小工具（MIT 协议，代码全部公开在 GitHub），把这些"人肉盯着、手动敲一下"的机械动作自动化。一个会往你终端里打字的工具，凭什么让人放心？凭源码可查 —— 每一行检测逻辑、每一次按键都能自己审计，也可以不用现成 EXE、直接从源码构建。双击即用，不需要装 Python，不需要配环境。

⏭ v2.0.5 新功能：After finish —— 跑完自动派下一个活

最常见的浪费其实不是被限流，而是任务跑完了，人不在。会话安安静静停在提示符上，几个小时的算力窗口就这么闲过去了。

现在：主界面每一行有个 After finish… 按钮，点开填一条提示词。这个会话跑完当前任务、空闲满一个稳定期后，工具自动把提示词输进去 —— 干完一轮再发一轮，直到你清掉提示词为止。睡前给每个窗口排好下一个活，醒来收货。
🛠 在 GUI 里怎么配
  1. 主界面表格里找到目标窗口那一行，在右侧 Action 区点 After finish…
  2. 弹窗里输入"跑完后要干的下一个活"，点 OK —— 按钮变成 After finish ✓，悬停可预览
  3. 要停下来：再点按钮，清空文本确定即可（勾选状态不影响这条指令的保存）
▲ 主界面：第一行已配置（After finish ✓），日志里可见自动派活的记录
▲ 点开按钮后的输入框：写上下一个任务，OK 即生效

判定"跑完"是严格的，四种"看着空闲但不是跑完"的状态都不会触发：

  • 从没见它跑过的窗口（新开的 shell 停在提示符上）—— 不算跑完
  • 屏幕上还挂着安全拦截提示 —— 那是被拦住，不是干完了
  • 刚被续过命、还在冷却期 —— 不重复注入
  • 模型恢复流程正在进行中 —— 不插队

这个功能发布前在真实会话上完整跑通过一遍：检测到空闲 → 工具自动输入提示词 → Claude Code 收到并开始执行新任务。

⇄ 重点功能：模型安全拦截自动恢复

先说这个功能解决的问题。做正经的安全审计、漏洞排查、协议分析这类工作时，模型的安全策略有时会把合法的编码任务误判为敏感内容，于是整轮回答直接中止，屏幕上留下这样一段：

API Error: ... safeguards flagged this message.
Our intentionally broad safeguards allow us to deliver more
capabilities faster, but can sometimes flag legitimate coding,
cybersecurity, and biology tasks.

Double press esc to edit your last message, or
try a different model with /model.

注意最后一行 —— Claude Code 自己给出的建议就是"换个模型试试"。问题在于：这个动作必须有人坐在电脑前手动做。你睡着了、出门了、或者同时开了四个窗口没注意到，这个会话就一直停在那里，什么都不干。

这个功能做的事：发现会话被拦住 → 按你配置的脚本换到备用模型 → 让它把这一轮做完 → 干满设定时长后切回原模型。全程不需要你在场。

默认的恢复脚本如下，每一步都可以在 Advanced 里自己改：

<confirm> 如果弹了选择框就按确认；没有就跳过
<esc> 会话正在出词就先打断 —— 否则下面的切换命令只会排队而不生效；空闲时什么都不做
/model opus 自己切到备用模型（已经在上面了就跳过，不重复切）
<confirm> 确认切换对话框
continue 在备用模型上把被拦的那一轮重做
<wait> 等 180 秒 —— 注意是实际运行时间，断网的时间不算；重试时自动加量
<esc> 同上：备用模型还在出词就打断它 —— 它的产出本来就不是你要的
/model fable 切回原模型
<confirm> 确认
<resume> 前几次尝试仍输 continue（原任务还有救）；只有多次被拦、走到"等备用模型跑完"那一次之后，才输入你预设的 After recovery 指令 —— 这时再重试只会再被拒，换新活才有意义。没预设就一直是 continue
🛠 在 GUI 里怎么配
  1. 右上角 Advanced… → 切到 Fable recovery 页
  2. 勾选 Enable Fable refusal-recovery（默认是关的）
  3. 在下方窗口列表里逐个勾选允许它接管的窗口 —— 没勾的窗口它一个键都不会碰
  4. （可选）同一行的 After recovery 列填一条指令：多次被拦、确认重试无望之后，切回原模型时输入它，而不是死磕 continue
  5. （可选）Wait for <wait> steps = 备用模型每轮跑多久（默认 180 秒，重试自动递增）；恢复脚本每一行也都能改
▲ Advanced → Fable recovery：脚本每一行都可以改，下方逐窗口勾选授权

会自动往终端里敲字的功能，最怕的是帮倒忙。所以它带了四条护栏，每一条都是真实踩过坑之后加的：

🔁
失败会升级，不会死磕
同一条拦截连试四次：每次给备用模型多 60 秒跑道（180/240/300 秒），最后一次改成等它这轮自然跑完再切回。四次都不行就明说放弃——并且仍会把窗口带回你选的模型，不会丢在备用模型上。
✋
你手动切了，它就不管了
如果你自己把某个窗口切到别的模型，工具会认为这是你的决定，自动取消该窗口的勾选，不再往回掰。想恢复接管，在 Advanced 里重新勾上即可。
🚪
默认关闭，逐窗口开启
装好就是关的。要用得自己去 Advanced 打开，并逐个勾选允许它操作哪些窗口。没勾的窗口它一个键都不会敲。
📋
失败就说失败
收尾时不只看"停在哪个模型"，还看拦截是不是真的解除了。做了无用功会明确写成警告，不会含糊报一句 done 蒙混过去。
🔍 另外两条自动行为：勾选的窗口如果漂到了别的模型（哪怕没被拦），会被自动拨回目标模型，最多 3 次就放弃；同一条拦截最多尝试 2 轮恢复，避免来回切一整夜。
它整体是什么？

Auto-Continue 是一款给 Claude Code 重度用户的 Windows 守护程序。它通过 Win32 UI Automation 实时读取所有 Windows Terminal 窗口的可见文本，识别各种"会话被卡住"的信号，然后把对应的按键送到那个终端，让长任务继续往下跑。

✅ MIT 开源，源码全公开可审计  ·  ✅ 单文件 EXE，25.5 MB  ·  ✅ 双击即用，无 Python 依赖
四个核心场景
⇄
安全拦截卡住 v2.0 新增
正经的安全/协议类编码任务被误判拦下，整轮停住。自动换到备用模型做完，再切回来。默认关闭，逐窗口开启。
⏰
5 小时窗口限制
识别到限制提示后解析出 reset 时刻，到点加缓冲后自动输入 continue。四种措辞、任意时区都认。
🌐
网络卡死 / 回答被截断
重试耗尽、连接错误、回答中途断流，都会每 10 分钟补一次 continue，直到恢复。会话一旦重新出词就立刻停手，不会反复打扰。
🪟
多窗口并行监控
同时开 5 个 Windows Terminal 跑不同任务？一个 GUI 全部看到。每个窗口独立倒计时、独立冷却、独立配置。

每一行就是一个 Windows Terminal 窗口，颜色和状态一目了然：

状态 含义
Idle 窗口正常，没有触发任何条件

怎么用？三步搞定
1
下载 EXE——文末提供 GitHub Releases 和百度网盘两个渠道，单文件 25.5 MB，不需要解压，不需要装任何运行时。
2
双击运行——GUI 直接弹出（没有命令行窗口），第一次跑建议先勾上 Dry-Run，看看检测和倒计时是否符合预期。Windows SmartScreen 提示时点"更多信息 → 仍要运行"。
3
点 Start——所有 Windows Terminal 窗口出现在表格里。5 小时限流、网络卡死、回答截断这三类是零配置的，点了 Start 就在管；要用模型恢复的话，进 Advanced → Fable recovery 打开开关，再勾选允许它操作的窗口。无人值守过夜时记得勾上 Keep Awake。
⚙️ 默认参数：每 60 秒轮询一次、reset 时刻后再等 60 秒才发送、卡死后每 600 秒补一次。最后这个数字是实测调出来的 —— 真实断网经常持续 40 到 90 分钟，按早期的 30 秒去捅会捅上百次，既没用又把日志淹了。
适合哪些人用？
  • 🔐 做安全 / 协议 / 底层相关开发的人——正经任务被安全策略误判的概率最高，模型恢复就是为这个场景做的
  • 🌙 夜间跑长任务的人——睡前布置任务，醒来要看到完成而不是卡在半路
  • ✈️ 出差 / 通勤期间挂任务的人——人不在电脑前，工具自动处理
  • 🖥️ 多窗口并行重构的人——3 个分支 3 个会话同时跑，统一监控
  • 🌐 网络不稳的用户——家宽抖动、公司代理偶发断流，自动恢复

关于安全性

工具只读所有 Windows Terminal 窗口的可见文本（通过 Win32 UIA），不会读网络流量、不会读凭据、不会上传任何数据。源码完全公开在 GitHub，可自行审计或自己编译：

  • 只向触发的那个终端发送按键，不会误打其它窗口
  • 发送前后保存并恢复原前台窗口焦点；抢不到焦点就放弃发送，绝不打进你正在用的程序
  • 会自动换模型的功能默认关闭，且必须逐窗口授权
  • 所有设置存在本地注册表，不联网、不上报、无遥测（仅检查更新时访问 GitHub）
  • 完整 Python 源码 + PyInstaller spec 公开，可自行从源码构建 EXE
